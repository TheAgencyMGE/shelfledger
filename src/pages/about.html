About

ShelfLedger tracks what you own, want, and used to own. There is no account and no server holding your collection, so there is nothing to sign up for and nothing to leak.

Where your data lives

In IndexedDB, a database built into your browser, on your device. Nothing else. Clearing site data deletes it permanently, and nobody can restore it for you. That is the trade for nobody being able to read it.

What this app requests

Three kinds of file, all from this same domain:

  • the pages, styles, and scripts;
  • data/catalog/*.json, the shared item catalogue, fetched when you search;
  • data/releases.json, the public release calendar.

Identical files for everyone. No query strings, no identifiers, no request bodies. No analytics of any kind, no error reporting, no third-party fonts, no embeds, no iframes.

The release radar

This is the one feature where you would expect a server. The release file is public and the same for every visitor. Your browser downloads it and compares it against your wishlist itself, so the flags you see were worked out on your device.

A scheduled job reads Funko's public catalogue pages once a day: new releases, coming soon, pre-orders, exclusives, and the limited edition drop calendar. It names itself honestly in its user agent and respects robots.txt. The result is committed to the repository, so you can read the diff. Prices and dates are whatever the source said when it ran.

Backups replace sync

Other trackers move your collection between devices by keeping it on their servers. Export writes the whole thing to one JSON file instead. Getting that file to another device is up to you, which is less convenient and a lot more private.

The catalogue

Around 19,800 items with official item numbers, seeded from public listings. It is definitely missing things, especially older releases and barcodes. If something you own is not there, open an issue or send a pull request. One item is one line.

You never have to wait for that. Anything you type in yourself is a real entry with the same standing as a catalogued one.

Scanning

Scanning uses your browser's own barcode decoder where one exists, and a copy of ZXing served from this domain where it does not. Camera frames are read and discarded in the page. No image and no scanned number is uploaded, and the camera stops when you close the scanner.
